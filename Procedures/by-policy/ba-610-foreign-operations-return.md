## 2. The cell-data-requirement contract (the BA-610-specific input)

- **Schema (the framework):** `cell-contract.ts` — the Zod `ReturnCellContractSchema`.
- **BA 610 instance:** `ba610-contract.json` (2 738 cells), loaded + validated via `loadReturnContract("BA610")`. Machine-generated by `gen-return-contract.py BA610` (an entry for EVERY XSD leaf cell — money, ratio, enum, text).

Each cell carries `regulatoryDefinition` + `citations[]` (P2); `valueType`/`currencyDimension`/`unit` (P5); `derivation`; `dataRequirements[]`; `applicability` (`entityScope: foreign-branch`); and `status`.

---

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 2 738 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("BA610")`.
2. **Resolves the value by `derivation.kind`** through the **`ba610-foreign-operations-fold`** projection, which aggregates each foreign operation's trial balance over the versioned **legal-entity tree**, applying per-currency analysis where the column is a currency axis and group-currency translation where the column is a group total. Cell values are **projections, never stored** (P1).
3. **Honours status — no fabrication (the BA-610-specific honesty posture):**
   - Every BA 610 cell carries status **`licence-day-data`**. The foreign-operations fold and the multi-currency / multi-entity substrate exist, but the **bank-in-formation has no foreign operations pre-licence-day**. The cells are fully defined and sourced, but the *data* that fills them only exists once a foreign branch / subsidiary is established (CLAUDE.md build-phase vs licence-day; Principle 5 multi-currency/multi-entity). Each cell's `statusReason` records this. **No silent fabrication, no zero-fill.**

> **Currency (P5).** Foreign-operation figures are reported per-currency (`by-currency`) where the column is a currency axis, and translated to the group reporting currency (`reporting`) for group totals — resolved from reference data, never hard-coded.

## 4. XSD validation before submission (BA-610-specific hard gate)

**Before** four-eyes review (PROC-FIN-BA-01 §7), the generated BA 610 instance MUST validate against `BA610.xsd` (typed wrappers for amount, percentage, enum, currency and text cells). **Fail-closed (Charter cmd 2):** an XSD-invalid instance is not eligible for review or submission.

---

## 5. Reconciliation invariants (BA-610-specific)

| Invariant | Assertion |
|---|---|
| **FX-translation consistency** | Each foreign-operation amount translated to the group reporting currency uses the period-end rate from the market-data reference set; a translated total that does not reconcile to (local-currency amount × rate) is a control failure. |
| **Per-currency completeness** | Every currency in which a foreign operation transacts is reported on its currency-analysis axis exactly once (Principle 5). |
| **Foreign-operation scope** | Every foreign branch / subsidiary in the legal-entity tree appears exactly once; a missing or double-counted operation is a control failure. |
| **Trace-to-source** | Every **populated** cell traces to its foreign-operations-fold source; a populated cell with no resolved source is a control failure (P1/P2). |
