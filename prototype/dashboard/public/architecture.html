Bank — stack architecture

Visual map of the bank's data substrate, event types, and runtime stack. Re-derives from the live registry on every load — the diagrams reflect what is on main right now.

1. Data architecture (ERD-ish)

Per Principle 1 the event store is the only authoritative durable artefact. Everything else — projections, caches, registers' derived views — is reproducible from it. Curated registers (markdown files) are canonical authoring locations for reference data the events couldn't capture (regulations, policies, mandates) and feed into projections via parsers.
