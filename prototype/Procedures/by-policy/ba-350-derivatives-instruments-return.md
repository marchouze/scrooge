## 2. The cell-data-requirement contract (the BA-350-specific input)

Cell population is **driven by the typed contract**, not hand-coded line logic:

- **Schema (the framework):** `prototype/v2-core/regulatory-returns/cell-contract.ts` — the Zod `ReturnCellContractSchema`, reusable across all BA returns.
- **BA 350 instance:** `prototype/v2-core/regulatory-returns/ba350-contract.json` (1 410 cells), loaded + validated via the return-contract registry (`return-contracts.ts` → `loadReturnContract("BA350")`). Machine-generated by `gen-return-contract.py BA350` (provenance — an entry for EVERY XSD leaf cell, no hand-omission).

### 2.1 Product-attribute requirements (Phase C batch 4 — derivative-type-keyed)

BA 350 cells genuinely require attributes a **derivative** product must carry. These attach to the **future, unapproved trading product** (`prd:bank:trading:market-risk-position`), never the live FX product:

| Attribute | Required? | Why | Clause |
|---|---|---|---|
| `derivativeType` | **required:true** on the instrument-type-defining rows (futures / call+put options written/purchased / swaps / forwards+FRAs) | the instrument-type row is the defining dimension of every BA 350 line; a derivative cannot be placed without its type | Basel MAR / CRE derivative reporting; SARB reg 28 |
| `tradingBookDesignation` | required:false | the Trading / Banking column heads (carried in nearly every BA 350 notional / fair-value column) slice the aggregate; the value still folds | Basel MAR trading-book boundary; SARB reg 28(3) |
| `underlyingAssetClass` | required:false | the underlying-asset-class column group (interest-rate / FX / equity / commodity / credit contracts) slices the instrument-type rows; sliced, not populate-or-die | Basel MAR / CRE; SARB reg 28 |

**This is the binding the NPA gate enforces** (`recon:npa-return-data-obligation-integrity`): a future derivative product cannot reach approval unless it captures — or tracks as a deferred gap — its owed `required:true` `derivativeType` attribute. The live FX product feeds NO `required:true` product-id cell and is therefore **not** blocked.

> **Honest substrate gap (Engineering Charter cmd 3 + 5).** The product-scope declaration schema does not yet model derivative-type / underlying-asset attributes; until extended, a future derivative product is approvable only by tracking each owed attribute as a `ProductDeferredGap`. Tracked, not hidden.

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 1 410 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("BA350")`.
2. **Resolves the value by `derivation.kind`:**
   - `direct` → fold the cell's figure from the **`ba350-derivatives-instruments-fold`** projection: the derivatives fold over the derivative book (futures / options / swaps / forwards / FRAs) by underlying asset class, exchange-traded vs OTC, trading vs banking book, gross notional + fair value. Cell values are **projections, never stored** (P1).
   - `sum` / `formula` → evaluate the SARB cell-coordinate expression (`derivation.expression`) over the already-resolved constituent cells.
3. **Honours status — no silent zeros, no fabrication:** every BA 350 cell is **`licence-day-data`** — the derivative positions that fill the notional / fair-value grid require a real derivative book the bank-in-formation does not run at scale pre-licence-day. The `statusReason` states this on every cell. The fold exists as substrate; the product-attribute `dataRequirements` bind **now** so the future derivative product is gated — the build-now value.

> **Gate coherence.** A `sourced` cell never carries a `required:true` product-attribute on an unapproved future product (that would fail `recon:ba-return-cell-contract`); the generator forces such a cell to `licence-day-data`.

## 4. XSD validation before submission (BA-350-specific hard gate)

**Before** the four-eyes review (PROC-FIN-BA-01 §7), the generated BA 350 instance MUST validate against `BA350.xsd`:

1. Serialise the populated cells into the BA 350 upload XML (the `BAxxxxxxxx` element envelope; the `Monetary1000` value wrappers; the instrument-type rows; the underlying-asset-class / trading-vs-banking / notional-vs-fair-value column structure; the maturity-band sub-rows).
2. Validate against `Regulations/SARB-PA/ba-returns/schemas/BA350.zip → BA350.xsd`.
3. **Fail-closed (Engineering Charter cmd 2):** an XSD-invalid instance is NOT eligible for review or submission; the failure is a blocking finding, never suppressed.

This is in addition to the build-time completeness guarantee enforced by `recon:ba-return-cell-contract` (every XSD cell has a contract entry — asserted for BA 350 alongside the other authored returns).

## 5. Reconciliation invariants (BA-350-specific)

| Invariant | Assertion |
|---|---|
| **Notional / fair-value tie** | The gross notional amounts and fair value of outstanding contracts by instrument type tie to the derivative sub-ledger: total gross notional = Σ per-instrument-type notional per `derivation.expression`; total fair value = Σ positive + negative fair values. A subtotal that does not equal its constituents is a control failure. |
| **Bought/sold + written/purchased symmetry** | For futures (bought / sold) and options (written / purchased), the per-leg notionals reconcile to the instrument-type totals; an asymmetry inconsistent with the book is a control failure. |
| **Trading-vs-banking split integrity** | The Trading + Banking notional / fair-value columns sum to the Total column for each instrument type (Reg 28 trading-book / banking-book boundary). |
| **Maturity-band roll-up** | The per-maturity-band sub-rows (less than 1 year / 1–5 years / more than 5 years) sum to the instrument-type total. |
| **Counterparty-credit reconciliation** | The derivative notional / fair value reconciles to the counterparty-credit-risk exposure feeding BA 200 (reg 23(15)–(19) / SA-CCR) — the same derivative book underlies both returns. |
| **Trace-to-source** | Every **populated** cell traces to its `ba350-derivatives-instruments-fold` source datum; a populated cell with no resolved source is a control failure (no value without a source — P1/P2). |
