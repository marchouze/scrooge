## 1. Form identity (BA-94x-specific — MULTI-SUB-FORM)

## 2. The cell-data-requirement contract (the BA-94x-specific input)

Cell population is **driven by the typed contract**, not hand-coded line logic:

- **Schema (the framework):** `prototype/v2-core/regulatory-returns/cell-contract.ts` — the Zod `ReturnCellContractSchema`.
- **BA 94x instance:** `prototype/v2-core/regulatory-returns/ba94x-contract.json` (1,133 distinct cells), loaded + validated via `loadReturnContract("BA94x")`. Machine-generated by `gen-return-contract.py BA94x` (an entry for EVERY distinct XSD leaf cell, no hand-omission).

### 2.1 Multi-sub-form identity (BA 900 `_1.._7` pattern)

The framework `cellRef` has **no sub-form axis** (like the BA 900 `_1.._7` handling). The sub-form (BA 941–944 `_1.._8`) is folded into each cell's **`label` + `regulatoryDefinition`** so the meaning is never lost. A leaf element **reused across sub-forms** (the shared country-code dimension) is carried **once** and its label names it as **"shared across the BA 941–944 series"** — honest provenance, not a single-sub-form pin. The build-time `recon:ba-return-cell-contract` independently re-extracts the XSD leaf set (each leaf once) and asserts exactly one contract entry per leaf — so the dedup is verified, not asserted by the generator.

### 2.2 Locational statistics are an AGGREGATE statistic — ZERO product-attribute requirements

The reported value is a **total** of financial claims / liabilities by instrument / currency / country — an aggregate locational statistic, **not** a product-static menu attribute. So BA 94x carries **NO `product-attribute` requirement**: no BA 94x cell gates a product; the live FX product and every future product are correctly unaffected. We do **not** manufacture any (no fabrication; no bulk-marking).

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 1,133 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("BA94x")`.
2. **Resolves the value by `derivation.kind`:**
   - `direct` → fold the figure from the **`ba94x-locational-banking-statistics-fold`** projection over the cross-border claims / liabilities sub-ledger (by instrument, currency and country of counterparty). Cell values are **projections, never stored** (P1).
3. **Honours status — no silent zeros, no fabrication:** **all 1,133 BA 94x cells are `status: licence-day-data`.** The fold exists as substrate, but every cell reports a **real** cross-border claim / liability total, and the bank-in-formation books **no cross-border claims pre-licence-day**. The `statusReason` states this on every cell.

> **Currency (P5).** Claims / liabilities are reported per-currency where the column names a currency axis ("All currencies, …" / Rand / foreign / US-dollar), else functional — resolved from reference data, never hard-coded.

## 4. XSD validation before submission (BA-94x-specific hard gate)

**Before** the four-eyes review (PROC-FIN-BA-01 §7), each generated BA 941 / 942 / 943 / 944 sub-form instance MUST validate against `BA94x_v20251031.xsd`:

1. Serialise the populated cells into the BA 94x upload XML per sub-form (the `BAxxxxxxxx` element envelope; `Monetary1000` value wrappers; the instrument × currency × country structure).
2. Validate against `Regulations/SARB-PA/ba-returns/schemas/BA94x.zip → BA94x_v20251031.xsd`.
3. **Fail-closed (Engineering Charter cmd 2):** an XSD-invalid instance is NOT eligible for review or submission; the failure is a blocking finding, never suppressed.

This is in addition to the build-time completeness guarantee enforced by `recon:ba-return-cell-contract` (every distinct XSD leaf has a contract entry — asserted for BA 94x alongside the other 28 authored returns).

## 5. Reconciliation invariants (BA-94x-specific)

| Invariant | Assertion |
|---|---|
| **Sub-form coverage** | Every BA 941–944 sub-form (`_1.._8`) the workbook defines must be populated where the bank holds the relevant claims / liabilities; an omitted in-scope sub-form is a control failure. |
| **Country totals tie** | For each sub-form, the by-country claims / liabilities must sum to the "All countries" / total line; a mismatch blocks submission. |
| **Currency totals tie** | The by-currency breakdown must sum to the all-currencies total for the same instrument / counterparty cut; a mismatch blocks submission. |
| **Claims vs liabilities consistency** | The claims and liabilities sub-forms must be internally consistent for the same instrument / currency / country (e.g. an instrument reported as a claim must not also appear as the same liability of the same counterparty); a divergence is a control failure. |
| **Hashtotal integrity** | The form's control hashtotals must equal the sum over their declared cell range; a mismatch blocks submission. |
| **Trace-to-source** | Every **populated** cell traces to its `ba94x-locational-banking-statistics-fold` source data; a populated cell with no resolved source is a control failure (no value without a source — P1/P2). |
