## 2. The cell-data-requirement contract (the BA-120-specific input)

- **Schema (the framework):** `cell-contract.ts` — the Zod `ReturnCellContractSchema`.
- **BA 120 instance:** `ba120-contract.json` (778 cells), loaded + validated via `loadReturnContract("BA120")`. Machine-generated by `gen-return-contract.py BA120` (an entry for EVERY XSD leaf cell — both money and ratio).

Each cell entry carries `regulatoryDefinition` + `citations[]` (P2); `valueType`/`currencyDimension`/`unit` (P5); `derivation`; `dataRequirements[]`; `applicability`; and `status`.

---

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 778 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("BA120")`.
2. **Resolves the value by `derivation.kind`:**
   - `direct` (money) → fold the line from the **income/expense GL categories** of the GL trial balance (`income-interest`, `income-other`, `income-trading`, `expense-interest`, `expense-impairment`) via the **`ba120-income-statement-fold`** projection. Cell values are **projections, never stored** (P1).
   - `direct`/`sum` (ratio) → compute the derived ratio (e.g. cost-to-income, net-interest-margin) from the already-resolved amount cells via the income-statement fold.
   - `sum` / `formula` → evaluate the SARB cell-coordinate expression over the constituent cells.
3. **Honours status — no silent zeros, no fabrication:**
   - All BA 120 cells are `sourced`: the income/expense GL categories exist now. With no real income/expense flows booked in the build phase, every line folds to an **honest 0** (CLAUDE.md build-phase vs licence-day).

> **Currency (P5).** Income-statement amounts are reported in the functional currency, resolved from reference data, never hard-coded.

## 4. XSD validation before submission (BA-120-specific hard gate)

**Before** four-eyes review (PROC-FIN-BA-01 §7), the generated BA 120 instance MUST validate against `BA120.xsd` (typed value wrappers — `Monetary1000` for amounts, the `Percentage` constraint for ratio cells, `totalDigits`/`fractionDigits`). **Fail-closed (Charter cmd 2):** an XSD-invalid instance is not eligible for review or submission.

---

## 5. Reconciliation invariants (BA-120-specific)

| Invariant | Assertion |
|---|---|
| **Profit composition** | NET PROFIT / (LOSS) FOR THE PERIOD equals the algebraic sum of the income, expense, impairment and tax line-items per the contract `derivation.expression`. |
| **Ties to retained earnings** | The reported net-profit-after-tax ties to the movement in retained earnings carried on the financial-position return (the balance-sheet form, BA 100). A break blocks submission. |
| **Ratio consistency** | Each `ratio` cell (e.g. cost-to-income) equals its formula over the resolved amount cells; a ratio that does not recompute from its numerator/denominator cells is a control failure. |
| **Trace-to-source** | Every **populated** cell traces to its `dataRequirements`; a populated cell with no resolved source is a control failure (P1/P2). |
| **GL agreement** | Income-statement totals reconcile to the income/expense side of the GL trial balance. |
