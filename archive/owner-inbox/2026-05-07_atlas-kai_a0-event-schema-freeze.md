## 1. Why a single A0 freeze

Both approved foundations want their event types registered at the substrate's genesis. Splitting the freeze across two passes risks (a) divergent envelopes (one for agent-runtime events, one for markets), (b) duplicate citation slots, (c) inconsistent multi-X discipline, and (d) replay-determinism breaking at the boundary. One freeze, one envelope, one citation discipline.

Concretely, this freeze fixes:

- The **common event envelope** (already published in `prototype/platform/event-store/types.ts` — re-affirmed here as the binding contract for every event in §4–§5).
- The **agent-runtime event types** (15) — substrate's own events.
- The **markets lifecycle event types** (24) — every event a CDM contract emits over its life.
- The **citation URN format** the P2 gate enforces.
- The **multi-X type-level fields** every event carries (P5).
- The **issuer / subscriber matrix** — who emits, who reads.
- The **replay semantics** — how each event behaves under as-of-replay (P1).
- The **schema-version policy** — how the freeze evolves under change-management (`change-management.md`).

After this freeze:

- Atlas can ship A1 (registry + identity issuer) against a stable schema set.
- Kai can ship M1 (CDM TypeScript bindings + equity event types) against the same set.
- Vera's Wave-4 #14 / #15 pipelines can hard-code their reads on `AgentEscalation` / `AgentDecision` shapes.
- Anya can register every event in the semantic layer with stable contract paths.
- Mira can pre-populate the citation URNs that the P2 gate will reject append on.

## 2. Common event envelope (binding)

The envelope already in `prototype/platform/event-store/types.ts`. Every event in §4 / §5 below conforms to this shape exactly. Per-event-type payloads are the only differentiator.

```ts
{
  event_id: string,        // UUIDv4; substrate-generated; immutable
  type: string,            // event-type name from §4 / §5; one of the registered set
  as_of: string,           // ISO 8601 UTC; the event's effective business time
  entity: string,          // legal-entity URN (e.g. BANK-ZA-001 today)
  actor: {                 // typed actor (P4)
    type: "system" | "human" | "service",
    id: string,            // for agents: `agent:<name>`; for humans: email; for services: service URN
  },
  citations: string[],     // ≥ 1 obligations-register URN (P2-gated at append time)
  payload: Record<string, unknown>,  // per-event-type contract; specified in §4 / §5
}
```

**Binding rules:**

- The envelope is **append-only**. No event is mutated after append; corrections are new events of a corresponding `…Corrected` type that supersede.
- `event_id` is generated by the substrate; consumers must not assume uniqueness within a type — uniqueness is across the whole stream.
- `as_of` carries business time (back-dating allowed for in-business-time corrections; the substrate adds `recorded_at` separately).
- `entity` per Principle 5 must be a real legal-entity URN; `BANK-ZA-001` until Imani's legal-entity tree publishes more.
- `citations` must be non-empty. The append-time P2 gate (`@platform/citation/gate.ts`, Vera #1, live) rejects events without citations.
- `payload` is the typed contract for the event type — described per-event below; Zod schemas live under `prototype/platform/event-store/_schemas/<type>.ts` (one file per type) so the registry is grep-able.

## 3. Citation URN format

Every URN cited under `citations` must resolve to an entry in `Regulations/_obligations-register.md` (Mira's curator role). The URN format already in use is `ORG-<DOMAIN>-<NN>` (e.g. `ORG-FC-13`, `ORG-PR-04`, `ORG-CY-01`). Internal policies cite as path strings (e.g. `Owner Inbox/2026-05-06_policy-register.md#section`) or as governance-token URNs (e.g. `GOV-FRAMEWORK-CEO-RESERVED`).

**At A0 freeze, the URN sets each event class will reference (Mira to ensure all are populated before the substrate goes live):**

- **Agent-runtime events** — `GOV-FRAMEWORK-CEO-RESERVED`, `ORG-CY-01` (Joint Standard 1 of 2024 — cyber resilience covers the substrate), `ORG-CY-09` (ISO/IEC 27001:2022), `ORG-PR-17` (BCBS Operational Risk), POPIA s.71 URN (automated decisioning — to be added).
- **Markets lifecycle events** — JSE Rules URNs (equities / debt / derivatives), `FMA` (Financial Markets Act) URNs, `ORG-FC-02` (FIC s.21 — counterparty CDD), `ORG-FC-13` (sanctions screening), IFRS 9 / IFRS 13 URNs, BCBS FRTB / SA-CCR URNs, ISDA Master clause-library URNs (Imani-curated), Joint Standard 1 of 2024 URNs (cyber on the trading estate).

The full obligations-register population for the markets surface is itself a Mira deliverable; this freeze names what each event-type *will* cite once those URNs land. Pre-A1 ship gate: every event type's citation set must resolve to existent URNs. Vera enforces.

## 6. Replay semantics — folding rules

Under as-of replay (Principle 1), every projection re-folds from the event log up to the as-of cut. Each event type's *folding rule* is summarised in the "Replay semantics" column above. The general rules:

- **Idempotent terminal events** (e.g. `TradeMatured`, `FullTermination`, `AgentRunCompleted`) — once present, fix the projection; later events on the same subject are rejected (or recorded as audit anomalies).
- **Latest-wins per key** (e.g. `MarkToMarketObserved`, `IdentityKeyRotated`) — the latest event with the same key supersedes earlier values; replay at as-of < latest yields the earlier value.
- **Cumulative folding** (e.g. `Reset`, `BarrierObservation`, `CorporateAction`) — projections accumulate the full sequence; the projection's value at any as-of is the fold of all events ≤ as-of.
- **Pair-coupled** (e.g. `AgentEscalation` ↔ `AgentEscalationDecided`; `SettlementInstructed` ↔ `SettlementConfirmed`) — projections track open / closed state by event pair; gap detection drives alerts.

The substrate's recon harness (`platform/recon/harness.ts`, Vera #2, live) re-folds the event log on every CI run and asserts projection determinism. A0 freeze locks the folding rules; any later change requires `change-management.md` + an `EventSchemaPublished` event with explicit migration notes.

## 8. Schema-version policy

The freeze is the **A0 baseline**. Going forward:

- Adding a new event type requires (a) a populated procedure or system-capability that consumes it; (b) Anya's semantic-layer entry; (c) Mira's URN coverage; (d) Vera review of the resulting Wave-4 #11 / #12 reconciliation impact. Approved by Atlas (substrate) + the issuing-agent's governance head.
- Adding a field to an existing event type follows the same rules with looser approvals (Atlas alone if the field is optional and back-compat).
- Removing a field or type is an `EventSchemaDeprecated` event with a transition window; the old shape replays correctly until it lapses.
- Every schema change emits an `EventSchemaPublished` event onto the event log itself (#4 in Atlas's runtime spec) — the schema register is itself event-sourced.
- Replay-determinism is the unbreakable invariant: any change that would alter a projection's value at a past as-of is forbidden. If a real-world correction is needed, it lands as a `…Corrected` event in the corrected event's stream, not as a schema change.
