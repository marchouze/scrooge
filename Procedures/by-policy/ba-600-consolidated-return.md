## 2. The cell-data-requirement contract (the BA-600-specific input)

- **Schema (the framework):** `cell-contract.ts` — the Zod `ReturnCellContractSchema`.
- **BA 600 instance:** `ba600-contract.json` (491 cells), loaded + validated via `loadReturnContract("BA600")`. Machine-generated by `gen-return-contract.py BA600` (an entry for EVERY XSD leaf cell — money, ratio, enum, text).

Each cell carries `regulatoryDefinition` + `citations[]` (P2); `valueType`/`currencyDimension`/`unit` (P5); `derivation`; `dataRequirements[]`; `applicability` (`entityScope: consolidated`); and `status`.

---

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 491 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("BA600")`.
2. **Resolves the value by `derivation.kind`** through the **`ba600-consolidation-fold`** projection, which aggregates each consolidated entity's trial balance over the versioned **legal-entity tree** and applies the prudential consolidation scope. Cell values are **projections, never stored** (P1).
3. **Honours status — no fabrication (the BA-600-specific honesty posture):**
   - Every BA 600 cell carries status **`licence-day-data`**. The consolidation fold and the legal-entity-tree substrate exist, but the **bank-in-formation has no consolidated subsidiaries pre-licence-day** — there is no group to consolidate. The cells are fully defined and sourced, but the *data* that fills them only exists once group entities are onboarded (CLAUDE.md build-phase vs licence-day). Each cell's `statusReason` records this. **No silent fabrication, no zero-fill** — the gap is honestly tracked, not hidden.

> **Currency (P5).** Group figures are presented in the group reporting currency (the `reporting` dimension), resolved from reference data, never hard-coded.

## 4. XSD validation before submission (BA-600-specific hard gate)

**Before** four-eyes review (PROC-FIN-BA-01 §7), the generated BA 600 instance MUST validate against `BA600.xsd` (typed wrappers for amount, numeric, enum and text cells). **Fail-closed (Charter cmd 2):** an XSD-invalid instance is not eligible for review or submission.

---

## 5. Reconciliation invariants (BA-600-specific)

| Invariant | Assertion |
|---|---|
| **Consolidation eliminations** | Intra-group balances and intra-group profits are eliminated on consolidation; a consolidated total that still carries an un-eliminated intra-group amount is a control failure. The intra-group eliminations tie to the bank-level intra-group analysis. |
| **Consolidation completeness** | Every entity in the prudential consolidation scope (per the legal-entity tree) is included exactly once; a missing or double-counted entity is a control failure. |
| **Solo-to-group tie** | The consolidated financial position aggregates the solo bank figures (form BA 100) plus consolidated subsidiaries, less eliminations. |
| **Trace-to-source** | Every **populated** cell traces to its consolidation-fold source; a populated cell with no resolved source is a control failure (P1/P2). |
