## 2. The cell-data-requirement contract (the CVA-specific input)

Cell population is **driven by the typed contract**, not hand-coded line logic:

- **Schema (the framework):** `prototype/v2-core/regulatory-returns/cell-contract.ts` — the Zod `ReturnCellContractSchema`.
- **CVA instance:** `prototype/v2-core/regulatory-returns/cva-contract.json` (53 cells), loaded + validated via `loadReturnContract("CVA")`. Machine-generated by `gen-return-contract.py CVA` (an entry for EVERY MR-prefix XSD leaf cell, no hand-omission).

### 2.1 CVA carries REAL counterparty / derivative product-attribute requirements

A CVA cell genuinely keys off the **derivative type** and the **CVA approach** a future OTC-derivative product must capture. The contract attaches a `product-attribute` requirement `ref: prd:bank:derivative:otc#<attr>` — `required:true` on the cell that **REPORTS** the CVA approach (the `CVAApproach` enum cell — the cell that defines which sub-form applies), and `required:false` on the monetary CVA-charge aggregates that are merely **sliced** by the derivative type (risk-class rows: interest rates / FX / equity / commodity / credit spread). The future OTC-derivative product (`prd:bank:derivative:otc`) is **unapproved**, so the NPA gate gates it once created, and the **live FX product is never matched** (exact product-id equality; the live FX product is FX spot/forward, not the future OTC-derivative product id). No bulk-marking, no fabrication.

## 3. Cell-population steps (delta on PROC-FIN-BA-01 §6 "data extraction")

For each of the 53 cells, the generator:

1. **Reads the contract entry** via `loadReturnContract("CVA")`.
2. **Resolves the value by `derivation.kind`:**
   - `direct` → fold the figure from the **`cva-capital-fold`** projection over the derivative / SFT counterparty book — CVA capital by approach, hedging set and counterparty credit-quality bucket. Cell values are **projections, never stored** (P1).
   - `sum` → evaluate the SARB cell-coordinate calculation over the already-resolved constituent cells.
3. **Honours status — no silent zeros, no fabrication:** **all 53 CVA cells are `status: licence-day-data`.** The fold exists as substrate, but every cell needs a **real** derivative / SFT counterparty book, which the bank-in-formation does not run pre-licence-day. The `statusReason` states this on every cell.

> **Currency (P5).** CVA capital amounts are reported in the functional currency, resolved from reference data, never hard-coded.

## 4. XSD validation before submission (CVA-specific hard gate)

**Before** the four-eyes review (PROC-FIN-BA-01 §7), the generated CVA instance MUST validate against `CVA_v06112025.xsd`:

1. Serialise the populated cells into the CVA upload XML (the `MRxxxxxxxx` element envelope; `Monetary1000` value wrappers; the approach × risk-class × hedging structure).
2. Validate against `Regulations/SARB-PA/ba-returns/schemas/CVA.zip → CVA_v06112025.xsd`.
3. **Fail-closed (Engineering Charter cmd 2):** an XSD-invalid instance is NOT eligible for review or submission; the failure is a blocking finding, never suppressed.

This is in addition to the build-time completeness guarantee enforced by `recon:ba-return-cell-contract` (every MR-prefix XSD cell has a contract entry — asserted for CVA alongside the other 28 authored returns).

## 5. Reconciliation invariants (CVA-specific)

| Invariant | Assertion |
|---|---|
| **Approach consistency** | The reported CVA capital must be computed by the approach the `CVAApproach` cell declares (BA-CVA / SA-CVA); a charge inconsistent with the declared approach is a control failure. |
| **Hedged ≤ reduced** | The K_Hedged (with eligible hedges recognised) CVA capital must not exceed the K_Reduced (hedges not recognised) figure for the same scope; a violation is a control failure. |
| **Risk-class decomposition** | The total CVA charge must equal the aggregate of the risk-class rows (interest rates / FX / reference + counterparty credit spread / equity / commodity) per the MAR50 aggregation; a divergence is a control failure. |
| **Hashtotal integrity** | The form's control hashtotals must equal the sum over their declared cell range; a mismatch blocks submission. |
| **Trace-to-source** | Every **populated** cell traces to its `cva-capital-fold` source data; a populated cell with no resolved source is a control failure (no value without a source — P1/P2). |
